## 4. Реализованные модули

| Файл | Ответственность |
|---|---|
| `data.js` | Исходные наборы задач и номер индивидуального варианта. |
| `task-service.js` | Чистые операции с задачами: создание, поиск, статистика, добавление, изменение статуса, переименование, удаление и обновление. Не обращается к DOM или хранилищу. |
| `task-selectors.js` | Возвращает новую выборку задач для активного фильтра. |
| `task-view.js` | Создаёт DOM-карточки, список, сводку и сообщение о пустом результате. Названия выводятся через `textContent`. |
| `form-validation.js` | Проверяет черновик формы и возвращает нормализованное значение либо объект ошибок. Не обращается к DOM или `localStorage`. |
| `task-storage.js` | Проверяет схему, читает и записывает JSON, восстанавливает исходный набор при некорректных данных и перехватывает ошибки. Получает объект `storage` аргументом. |
| `main.js` | Хранит состояние интерфейса, переключает режим формы, связывает события с сервисом и хранилищем. |

Объект `storage` передаётся в функции явно, чтобы модуль можно было проверять с имитацией хранилища без браузера. JSON проверяется до использования: успешный `JSON.parse` подтверждает только корректность синтаксиса строки, но не версию и не структуру данных.

## 8. Проверка восстановления и ошибок

| Случай | Поведение, заложенное в модуле | Проверка |
|---|---|---|
| Записи нет | Возвращается независимая копия исходного набора с `source: "initial"`. | Автоматическая проверка пройдена. |
| Корректная запись | Задачи восстанавливаются из JSON с `source: "storage"`. | Автоматическая проверка пройдена. |
| Повреждённый JSON | Приложение получает резервный исходный набор и сообщение об ошибке. | Автоматическая проверка модуля пройдена; браузерный сценарий требует прогона. |
| Неизвестная версия или неверная схема | Сохранённые данные отклоняются целиком, используется исходный набор. | Автоматическая проверка модуля пройдена. |
| Ошибка `getItem`, `setItem` или `removeItem` | Исключения перехватываются и возвращаются как управляемые ошибки. | Автоматические проверки пройдены. |
| Сброс | Удаляется только ключ текущего набора. | Проверка функции удаления ключа пройдена. |
| Общий и индивидуальный наборы | Используют отдельные ключи `...:demo` и `...:variant`. | Предусмотрено в интеграции; проверить в браузере. |

## 12. Отладка и клавиатура

Для отладки установить точку останова в `handleFormSubmit` и проверить:

- исходные строки `draft`, полученные из `FormData`;
- нормализованный объект `validation.value` или объект `validation.errors`;
- результат `addTask` либо `updateTask`;
- строку JSON с полями `version` и `tasks` в хранилище.

Клавиатурное управление необходимо проверить в Chrome: `Tab` переводит фокус между полями и кнопками, `Enter` отправляет валидную форму, `Space` активирует сфокусированные кнопки. При начале редактирования фокус должен перейти в поле названия; при отмене — в поле id. После удаления фокус возвращается на соответствующую кнопку либо на активный фильтр, если карточка исчезла.

Фактические значения DevTools и наблюдения клавиатурной проверки: заполнить после локального запуска.
