## 1. Цель и результат работы

**Цель работы** — расширить приложение из ПР3 формой создания и редактирования задач, освоить нативную и прикладную проверку данных, а также организовать сохранение состояния приложения в `localStorage`.

В ходе работы реализованы:

- обработка отправки формы через событие `submit`;
- получение значений полей с помощью `FormData`;
- проверка данных на уровне HTML и JavaScript;
- отображение ошибок около соответствующих полей;
- использование одной формы в режимах создания и редактирования;
- сохранение списка задач в формате JSON;
- проверка структуры загруженных данных;
- восстановление исходного набора при повреждённой записи или ошибке чтения;
- сохранение изменений после добавления, редактирования, изменения статуса и удаления задачи;
- раздельное хранение общего и индивидуального наборов.

Итоговое приложение сохраняет основную функциональность ПР3 и дополняет её управлением задачами через форму и `localStorage`.

## 6. Реализованная функциональность

### 6.1. Создание задачи

Пользователь вводит идентификатор, название и приоритет. После отправки формы данные проходят прикладную проверку. Если ошибок нет, вызывается операция добавления задачи, интерфейс обновляется, а новый список сохраняется в `localStorage`.

Повторяющийся идентификатор отклоняется. При отказе список и сохранённые данные не должны изменяться.

### 6.2. Редактирование задачи

Редактирование выполняется через ту же форму, которая используется для создания. При выборе действия `edit` поля заполняются данными выбранной задачи, а идентификатор блокируется от изменения.

Функция `updateTask` изменяет только `title` и `priority`. Идентификатор `id` и статус `completed` сохраняются. Исходный массив и его объекты не изменяются.

### 6.3. Валидация формы

Проверка разделена на два уровня:

| Уровень | Проверки |
|---|---|
| HTML | Обязательность полей, минимальное значение идентификатора, шаг числового поля и максимальная длина названия. |
| JavaScript | Уникальность идентификатора, непустое название после `trim()`, допустимый приоритет и наличие редактируемой задачи. |

Обычные значения `FormData` читаются как строки, поэтому идентификатор явно преобразуется в число. Поле `id` в режиме редактирования отключено и не попадает в `FormData`; в этом случае используется значение `editingId`.

### 6.4. Сохранение и восстановление данных

Для хранения используется JSON-объект с номером версии и массивом задач. При загрузке проверяются версия и структура данных. Если запись отсутствует, используется копия исходного набора. Если JSON повреждён, версия неизвестна, схема некорректна или чтение завершается исключением, приложение получает резервный исходный набор и сообщение об ошибке.

Для общего и индивидуального наборов используются отдельные ключи:

```text
tip-js-practice-04:demo
tip-js-practice-04:variant
```

Сброс удаляет только ключ текущего набора. Метод `localStorage.clear()` не используется, чтобы не затрагивать другие данные origin.

- `Tab` переводит фокус между полями и кнопками;
- `Enter` отправляет валидную форму;
- `Space` активирует сфокусированные кнопки;
- при начале редактирования фокус переходит в поле названия;
- при отмене редактирования фокус возвращается в поле id;
- после удаления фокус возвращается на соответствующую кнопку либо на активный фильтр, если карточка исчезла.

Фактические значения DevTools и наблюдения клавиатурной проверки необходимо заполнить после локального запуска.
