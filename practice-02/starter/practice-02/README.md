## 4. Модель данных и функции

Каждая задача представлена объектом с четырьмя полями:

- `id` — положительное безопасное целое число; в пределах одного списка идентификаторы уникальны.
- `title` — строка длиной от 1 до 100 после `trim()`; в объект записывается строка без краевых пробелов.
- `completed` — логическое значение `true` или `false`; при создании новой задачи устанавливается `false`.
- `priority` — одно из значений `low`, `medium`, `high`; значение по умолчанию — `medium`.

Идентификатор не равен индексу массива: индекс обозначает текущую позицию записи и может измениться после удаления соседней задачи, а `id` остаётся идентификатором самой задачи. Поэтому поиск выполняется по свойству `task.id`, а не обращением `tasks[id]`.

`getTaskStats` возвращает числовой `progress`, чтобы результат можно было использовать в дальнейших вычислениях без предварительного округления. Округление до одного знака выполняется только при отображении через `toFixed(1)`.

При добавлении создаётся новый массив с помощью spread и добавляется новый объект задачи. При изменении статуса или названия создаются новый массив и новый объект только изменяемой задачи; остальные записи могут повторно использоваться, потому что функция их не изменяет. При удалении создаётся новый массив без выбранной задачи. Входной массив и его объекты не изменяются.

| Функция | Назначение и успешный результат | Поведение при отказе / отсутствии |
|---|---|---|
| `createTask(id, title, priority)` | Проверяет поля и возвращает `{ ok: true, task }`; новая задача получает `completed: false`. | Возвращает `{ ok: false, error }` при некорректном `id`, названии или приоритете. |
| `findTaskById(tasks, id)` | Возвращает найденный объект задачи по `id`. | Возвращает `undefined`, если задача отсутствует. |
| `getPendingTasks(tasks)` | Возвращает новый массив задач, у которых `completed === false`. | Для пустого списка возвращает новый пустой массив. |
| `getTaskTitles(tasks)` | Возвращает новый массив названий в исходном порядке. | Для пустого списка возвращает `[]`. |
| `getTaskStats(tasks)` | Возвращает `{ total, completed, pending, progress }`; все поля — числа. | Для пустого массива все четыре значения равны `0`. |
| `addTask(tasks, id, title, priority)` | Создаёт задачу через `createTask` и возвращает `{ ok: true, tasks }` с новым массивом. | Отклоняет некорректные поля и повторяющийся `id`; возвращает `{ ok: false, error }`. |
| `setTaskCompleted(tasks, id, completed)` | Принимает только boolean и возвращает новый массив с обновлённым объектом задачи. | Ошибка при неверном `id`, не-boolean значении или отсутствии задачи. |
| `renameTask(tasks, id, title)` | Проверяет название и возвращает новый массив с новым объектом переименованной задачи. | Ошибка при неверном `id`, некорректном названии или отсутствии задачи. |
| `removeTask(tasks, id)` | Возвращает новый массив без задачи с указанным `id`, сохраняя порядок остальных. | Ошибка при неверном `id` или отсутствии задачи. |

Распределение ответственности между файлами: `data.js` содержит общий и индивидуальный наборы данных; `task-service.js` содержит прикладные функции без консольного вывода и зависимости от конкретного набора; `main.js` собирает и показывает сценарии; `checks.js` проверяет контракты функций; `examples/functions-and-references.js` демонстрирует работу функций, ссылок и spread.

## 9. Вывод

В практической работе логика приложения была разделена на отдельные функции и ES-модули. Данные представлены массивом объектов; для поиска, отбора и преобразования использованы `find`, `filter` и `map`. Создание и изменение задач выполняются без изменения переданного массива и его объектов: возвращаются новые массивы, а при изменении записи создаётся новый объект этой записи.

Функции возвращают результат операции, а вывод в терминал выполняется в `main.js`. Для ожидаемых отказов используется объект `{ ok: false, error }`, поэтому ошибка, например повторное добавление `id`, не прерывает сценарий и не заменяет текущее состояние. Результаты проверены 35 общими и тремя собственными группами проверок: все 38 прошли.

В эксперименте со стрелочной функцией показано, что при блочном теле нужен `return`: без него результатом было бы `undefined`, после исправления `square(4)` возвращает `16`.
