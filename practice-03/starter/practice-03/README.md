## 2. Запуск

Все команды ниже выполняются из папки `practice-03`:

```bash
npm run check:service
npm start
```

Устанавливать зависимости через `npm install` не требуется. После запуска открыть:

```text
http://127.0.0.1:5503/
http://127.0.0.1:5503/index.html?dataset=variant
http://127.0.0.1:5503/examples/dom-events.html
http://127.0.0.1:5503/checks.html
```

Остановка сервера: `Ctrl+C`. При блокировке `npm.ps1` в PowerShell использовать `npm.cmd start` и `npm.cmd run check:service`.

## 4. Организация кода

| Файл | Назначение |
|---|---|
| `data.js` | Общий массив и индивидуальный набор варианта 4. |
| `task-service.js` | Прикладные операции с задачами из ПР2; DOM не используется. |
| `task-selectors.js` | Получение нового массива по фильтру `all`, `pending` или `completed`. |
| `task-view.js` | Создание DOM-карточек, обновление списка, сводки и пустого состояния. |
| `main.js` | Хранение текущего массива и фильтра, делегирование событий, вызовы сервиса и повторная отрисовка. |

Полный массив хранится в `currentTasks`, выбранный фильтр — в `currentFilter`. Фильтрация создаёт отдельную видимую выборку и не удаляет скрытые задачи. События списка делегируются на `ul#task-list`, поэтому для каждой карточки отдельный обработчик не назначается.

## 9. Отладка и клавиатура

В DevTools поставьте точку останова на строке `const rawId = card.dataset.taskId;` в `src/main.js`. Зафиксируйте реальные значения `event.target`, `event.currentTarget`, `rawId`, числового `id`, `action` и результат функции сервиса. Отдельно проверьте карточку с `data-task-id="777"` и `data-task-id="4abc"`.

Проверьте управление клавиатурой: `Tab` переводит фокус на кнопки фильтров и действий, `Enter`/`Space` активируют кнопку, после переключения фокус остаётся на соответствующем действии, а после удаления переходит на активный фильтр, если карточка исчезла.

**Фактические наблюдения:** заполнить после проверки в браузере.

## 10. Вывод

В практической работе реализован браузерный интерфейс списка задач на основе модели и функций предыдущей практики. DOM-элементы создаются программно, а пользовательские названия выводятся через `textContent`. Обработчики событий назначаются контейнерам один раз; действия карточек обрабатываются делегированием через `closest`.

Полный массив задач хранится отдельно от выбранного фильтра. После изменения статуса или удаления вызываются функции прикладного модуля, а интерфейс повторно отображается из обновлённого состояния. Сводка рассчитывается по всему списку, а не только по видимым карточкам. Между перезагрузками состояние не сохраняется, что соответствует границам ПР3.

Перед сдачей необходимо дополнить отчёт фактическими результатами запуска, версиями окружения, наблюдениями пяти экспериментов, результатами DevTools и клавиатурной проверки.
